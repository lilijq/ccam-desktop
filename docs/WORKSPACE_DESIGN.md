# 分屏工作区设计

工作台围绕一个项目展开：对话决定下一步，文件与 Git 用来检查结果，终端保留交互式操作。四者是可同时查看的工作内容，不是四个互相隔离的页面。

## 视觉方向

沿用用户指定的现代中性黑。底色 `#111111`，侧栏 `#080808`，窗格表面 `#1C1C1C`，分隔线 `#303030`，正文 `#F5F5F5`，次要信息 `#A3A3A3`。颜色仅用于代码语法、文件类型和需要注意的状态，避免额外装饰。

界面使用系统字体，主要操作 13px，辅助信息 11–12px。代码使用 13px 系统等宽字体；路径与文件名按正常界面字体显示。内容左对齐，间距以 4/8/12/16px 为基础。

## 布局

项目侧栏保留在左侧。工作区内部以可拖动分隔线构成窗格，每个窗格有紧凑标题栏。分割、聚焦和关闭使用图标与提示，关闭只隐藏视图。顶栏的四个内容入口仍可直接使用。

```text
项目与对话   项目名                         对话 文件 Git 终端  分屏
             ┌────────────────┬──────────────────────────┐
             │ 对话        ⋯  │ 文件                  ⋯  │
             │                │ 目录树 │ 文件名           │
             │                │        │ 代码 + 行号      │
             │                ├──────────────────────────┤
             │ 输入框         │ 终端                  ⋯  │
额度 / 设置  └────────────────┴──────────────────────────┘
```

左右分割用于一边提问一边检查代码；上下分割用于代码与终端。每种内容在项目内保留一个实例，避免同一个对话或终端被重复启动。窗格太窄时临时聚焦一个内容，恢复宽度后回到原布局。

## 文件体验

目录以真正的树呈现，展开箭头表达层级，图标区分文件夹与文件类型。代码区显示语言、行号和语法颜色，支持编辑、查找和保存；外部修改冲突保留草稿，不覆盖磁盘内容。

此设计借鉴代码编辑器的工作方式，不嵌入完整 VS Code，也不暗示具有语言服务器、插件或编译诊断能力。所有显示与本次验收均在本地完成。

## 验收重点

- 拖动分隔线、改变方向、聚焦、关闭和切项目后保持内容与比例。
- 输入框、代码区和终端获得各自正确的键盘焦点。
- Rust 文件中的关键字、类型、字符串和注释可区分，行号与正文滚动一致。
- 窄窗格下按钮、查找栏与文件树入口可用。
- 分屏与文件浏览不发送 Claude 请求，代理设置保留原有可修改入口。
